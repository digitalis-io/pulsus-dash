## Context

[ADR-0001](0001-rust-wasm-everywhere.md) made the server Rust so it could share crates with the
browser (planner IR, wire codec, scope rewrite). With the client now TypeScript
([ADR-0014](0014-typescript-react-web-client.md)), that sharing is gone for the first milestones,
and the server's job is web and operations work: HTTP, OIDC, Postgres, PulsusDB calls, telemetry,
and later inventory connectors for the clouds and Kubernetes
([16](../product/16-infrastructure-model.md)). Go is already used for the Terraform provider
([ADR-0011](0011-terraform-provider-in-go.md)).

## Decision

The BFF (`pulsus-dash`) is one statically linked Go binary.

| Concern | Choice |
|---|---|
| Toolchain | Go pinned in `server/go.mod` (`go` and `toolchain` directives); `CGO_ENABLED=0` |
| HTTP | `net/http` with the `chi` router; HTTP/2 via the standard library |
| API contract | **Spec first:** `api/openapi.yaml` (OpenAPI 3.1) is the single source. Go server interfaces are generated by `oapi-codegen` (chi, strict server); TS types by `openapi-typescript` for the client. Both are regenerated and compared in CI (`ci:api-gen`) |
| Postgres | `pgx/v5` with `sqlc` (queries in `server/queries/*.sql`, generated code committed); migrations as SQL files run by `goose` from an embedded `embed.FS` |
| OIDC | `go-oidc` + `golang.org/x/oauth2` (code flow with PKCE) |
| Arrow (later) | Apache Arrow Go (`arrow-go`) for the BFF → browser Arrow stream; until then JSON frames ([ADR-0014](0014-typescript-react-web-client.md) §5) |
| Telemetry | OpenTelemetry Go SDK; `log/slog` structured logs |
| Static assets | The client build embedded with `embed.FS`, pre-compressed at build time ([T19](../technical/T19-deployment.md) T19-003) |
| Later connectors | Official Kubernetes client and AWS, Azure and GCP SDKs for the [16](../product/16-infrastructure-model.md) inventory |

**Layout.** One Go module in `server/`: `cmd/pulsus-dash` (main), `internal/<module>` per T06
module (`config`, `core`, `store`, `gateway`, `auth`, `pulsusdb`, `boards`, …), `migrations/`,
`queries/`, `sqlc.yaml`. `internal/gateway` is the only package that imports `chi` or the generated
server; `internal/store` is the only package that imports `pgx` or the sqlc output; and
`internal/pulsusdb` is the only package that builds requests to PulsusDB. `depguard` in
golangci-lint enforces this (T06-001, T06-005, T11-023).

**Query validation.** The BFF does not parse PromQL or LogQL in v1. It validates by asking PulsusDB
(a query that fails to parse returns PulsusDB's error with its position, mapped to the error
envelope). Browser-side diagnostics come later from PulsusDB's Rust parser crates compiled to WASM
([ADR-0014](0014-typescript-react-web-client.md) §2).

**Wire schema.** The Arrow schemas of [T04](../technical/T04-wire-format-and-data-plane.md) are
defined once, language-neutrally, in `wire/schemas/*.yaml` (field names, Arrow types, metadata
keys), with golden IPC fixtures in `wire/fixtures/`. The Go writer must reproduce the fixtures and
the Rust engine must decode them to the expected values (`unit:codec-roundtrip` runs on both sides).

**CI gates (server).**

| Gate | Command |
|---|---|
| `ci:go-lint` | `golangci-lint run` (pinned version; includes `depguard`, `gosec`, `errcheck`, `staticcheck`) |
| `ci:go-test` | `go test -race ./...` |
| `ci:govulncheck` | `govulncheck ./...`; any reachable vulnerability fails |
| `ci:go-mod` | `go mod verify`; `go mod tidy` leaves no diff; `GOFLAGS=-mod=readonly` |
| `ci:api-gen` | `oapi-codegen`, `openapi-typescript` and `sqlc generate` leave no diff |
| `ci:migrations` | `squawk` on `server/migrations/*.sql` (T11-013) and an up-from-empty run on Postgres |
| `itest` | `go test -tags itest ./...` against the dev compose stack (Postgres, OIDC test IdP, `pulsus-fake`) |

Tools other than `golangci-lint` are pinned with `tool` directives in `server/go.mod`.

## Consequences

- Rust stays for the browser chart engine, the browser-side parsers, and the headless renderer for
  server-side chart images (ALR-066), which becomes a separate Rust binary in the
  `pulsus-dash-render` image called by the Go notifier ([T19](../technical/T19-deployment.md) §4.2).
- Code that T06 planned to share between browser and server as Rust crates (`pulsus-plan`,
  `pulsus-colexec`, `pulsus-pyramid`, `dash-wire`, `pulsus-dash-scope`) is now implemented once per
  side where both need it, held together by shared fixtures. [T07](../technical/T07-scene-query-planner.md)
  and T13 (draft) must be revised before their milestones.
- Data-scope enforcement (T10 (draft), M-UI6) needs PromQL and LogQL rewriting in Go. The
  Prometheus project's Go PromQL parser covers PromQL; LogQL needs a Go parser or PulsusDB-side
  enforcement. This is an open question for T10, not a blocker for M-UI1 (full-tenant scope only).
- [T18](../technical/T18-security.md) §4.11 (`cargo-deny`, `cargo-vet`, `cargo-auditable`) is
  replaced for the server by the gates above plus `go version -m` build info and a CycloneDX SBOM;
  T18 is revised with the client changes of ADR-0014.
- The internal API between roles (T06 §5.4) uses JSON over HTTP/2 with mTLS instead of `bincode`.
